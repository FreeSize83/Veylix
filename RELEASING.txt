Как выпускать обновления Veylix (GitHub Releases)
================================================

Veylix проверяет релизы в https://github.com/FreeSize83/Veylix/releases и обновляется
сам, если в релизе есть готовый пакет. Ниже — точный формат, который он понимает.

ВЕРСИЯ
  * Единственный источник: строка  public const string Version = "X.Y.Z";  в src\Program.cs.
    Из неё же берётся версия сборки Veylix.exe (src\AssemblyInfo.cs) — менять в одном месте.
  * Формат: три числа X.Y.Z (например 2.3.0). Новая версия должна быть строго больше предыдущей:
    сравниваются числа, поэтому 2.10.0 новее 2.9.0.
  * Тег релиза на GitHub: v + версия, например v2.3.0.

ВЫПУСК РЕЛИЗА
  1. Поднимите версию в src\Program.cs и добавьте запись о ней в начало списка в src\WhatsNew.cs
     (1–4 коротких пункта: их покажет окно «Что нового» после обновления; без записи тесты
     не пройдут). Закоммитьте изменения.
  2. Запустите release.bat. Он соберёт Veylix.exe, прогонит тесты, проверит, что версия
     сборки совпадает с Program.Version, и создаст в папке release\:
        Veylix-X.Y.Z-win-x64.zip          — Veylix.exe и README.txt в корне архива
        Veylix-X.Y.Z-win-x64.zip.sha256   — SHA-256 архива
  3. GitHub → FreeSize83/Veylix → Releases → «Draft a new release»:
        Tag:     vX.Y.Z (создать новый тег)
        Title:   Veylix X.Y.Z
        Описание: что изменилось — Veylix покажет этот текст в окне обновления.
        Assets:  перетащите ОБА файла из release\.
  4. «Set as a pre-release» НЕ отмечать (предварительные релизы Veylix не предлагает).
     «Publish release».
  5. Проверка: на другом компьютере (или в старой версии) — Обновления → «Проверить обновления»:
     должна появиться версия X.Y.Z с кнопкой «Обновить до X.Y.Z».

ЧТО VEYLIX ПРОВЕРЯЕТ ПЕРЕД УСТАНОВКОЙ
  * Релиз не черновик и не предварительный; тег — версия вида vX.Y.Z; версия новее установленной.
  * Пакет называется ровно Veylix-X.Y.Z-win-x64.zip и скачивается только с
    github.com/FreeSize83/Veylix/releases/download/.
  * SHA-256: сначала «digest», который GitHub сам вычисляет для каждого загруженного файла и отдаёт
    через API, иначе — файл .sha256 из того же релиза. Без контрольной суммы установка не начнётся.
  * Размер совпадает с данными релиза; архив распаковывается без выхода за пределы папки;
    внутри есть Veylix.exe; это сборка .NET с именем Veylix и версией X.Y.Z (читаются только
    метаданные — код при проверке не запускается).

КАК ПРОХОДИТ ОБНОВЛЕНИЕ У ПОЛЬЗОВАТЕЛЯ
  1. «Обновить» → подтверждение → загрузка с прогрессом (можно отменить) → проверка пакета.
  2. Копия текущего Veylix.exe запускается как помощник (%LOCALAPPDATA%\Veylix\updates\helper),
     Veylix закрывается обычным образом (останавливает обход).
  3. Помощник ждёт закрытия, кладёт новый файл рядом и атомарно заменяет Veylix.exe;
     старый файл остаётся рядом как Veylix.exe.backup-<старая версия>.
  4. Новая версия запускается и подтверждает старт. Если подтверждения нет за 60 секунд —
     помощник возвращает прежний Veylix.exe и запускает его; пользователь увидит причину.
  5. Если обход был включён — после обновления он включится снова.
  Настройки, темы, журналы (%LOCALAPPDATA%\Veylix) и папка zapret рядом с exe не затрагиваются.
  Журнал установки: %LOCALAPPDATA%\Veylix\updates\update.log

ЧЕГО НЕ ДЕЛАТЬ
  * Не публикуйте только исходники (Source code zip или BeeBot-source.zip) — это не установочный пакет,
    Veylix такой релиз не установит и честно напишет почему.
  * Не используйте теги без версии (например «Releases») — такие релизы Veylix пропускает.
  * Не меняйте файлы релиза после публикации: digest пересчитается, но пользователи, начавшие
    загрузку, получат несовпадение и установка остановится (это защита).

ТЕКУЩЕЕ СОСТОЯНИЕ РЕПОЗИТОРИЯ (на момент добавления автообновления)
  Единственный релиз «Veylix Beta 0.1» имеет тег «Releases» и содержит только BeeBot-source.zip.
  Veylix его пропускает («нет стабильного релиза с номером версии»). Первый совместимый релиз —
  v2.2.0 с файлами из release.bat.
